# ROM Tuner on M30s

Both the compact `org.m30s.tuner` app and the adapted tablet `org.tablet.tuner` app were installed and their complete APK hashes matched the host artifacts. The tablet app updated in place with its original external signing identity; existing data was retained. Both apps remain enabled during validation.

The tablet interface retains its graphs, navigation and performance tile. CPU readings use Exynos policy4 for performance cores and policy0 for efficiency cores. GPU uses the actual Mali kHz interface; temperature uses the BIG thermal zone. CPU maximum selectors use the device's advertised frequency tables. Unsupported MediaTek, overclock and thermal-override pages are excluded.

The shared root backend verified a tablet-app-directory touch request changing duration to 200 ms, then restored the prior 300 ms. The earlier compact-app request changed 150 to 200 ms and restored 150. Both clients received actual readback state. A backend restart reapplied saved duration; the same system server remained alive. No thermal-control writes were performed. Profile mappings and rejection/rollback behavior passed 14 host regressions. The root filesystem was returned to read-only after scoped backend/init installation.

The original tablet app's pending request queue was present during initial adaptation; its supported Responsive request applied, while an oversized request was rejected. Fresh-install no-default-change behavior is covered separately by host tests. Named profiles and unsupported tablet features remain unavailable. Performance gains, enforcing-policy compatibility and restart persistence through a full phone reboot have not been established.
