# Tablet ROM Tuner adaptation

Copied from `rom-tuner/src`, `rom-tuner/res` and `rom-tuner/AndroidManifest.xml` in `manvindar/tb-x606v-android17`, local source checkout d718d61f95bba296a1093cdb8076a17aa1b6247d. Upstream source identifies the Android 16 port ROM Tuner as its original home (source sync 0fb0152, 2026-11-02). The newest upstream changes (a676333 profile Use button and pending values, c8f3b69 and 8523f50 overclock lists) were merged in from `tb-x606v-android16-port` at `8523f50` (2026-11-04); the overclock code arrives with them but is not reachable on the M30s.

The M30s adaptation retains the app package and existing UI code. It replaces the performance and memory pages; maps Exynos cluster ordering, Mali clock and BIG temperature; bounds selectable M30s profiles; lists only the pages and controls the backend publishes (`Caps.pages`, `Caps.has`; see `../FEATURES.md`) and sends direct routes to pages the device lacks (Picture, Overclock) to the home screen; and queues atomic backend requests. The Picture and Overclock code remains as upstream lineage but is not reachable. Root writes use the separately reviewed M30s backend, never the tablet daemon.

Capability-driven options (`Caps.java`, state key `caps=2`): option lists, profile descriptions, graph rules and the comparison baseline come from the lists the backend publishes; nothing hardcodes a frequency, governor, scheduler or congestion algorithm, and a control without a published list is hidden (touch boost on a kernel without `input_boost_m30s`, GPU limit without the Mali table, storage/network rows without UFS disks or a TCP list). The quick settings tile steps only through accepted profiles. The overview no longer lists the tablet's Profile, Overclock and Thermal rows. `Caps` has no Android types and is tested by `tools/tuner/tests/CapsTest.java`.
